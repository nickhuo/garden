## Part 2 — Research Radar（HuggingFace Papers）

### TL;DR — 本日 research 风向
今日 HF 被 **agent 工程化**主导：技能（skill）生成与审计（COLLEAGUE.SKILL / OpenSkillEval）、agent harness 的安全与系统级 scaling（Trojan 防御 / "从模型 scaling 到系统 scaling"），以及一波 **on-policy distillation** 的 post-training 细化。第二主线是 **agentic search / 长时程** 的可靠性（GrepSeek、SAAS、LongDS-Bench、LongTraceRL）。对 Nick 的 Skills 与 agent harness 经验，今天信息密度极高。

### Agent frameworks & self-evolution

#### 🟢 [2605.31264] COLLEAGUE.SKILL：专家知识蒸馏自动生成 AI 技能
- **Problem:** 专家知识散落在 traces 里，不是 agent 可直接用的清晰指令。
- **Method:** trace→skill 自动蒸馏，把专家行为打包成 skill card。
- **Key result:** 已发布 215 个 skills、165 位贡献者、累计 100k+ stars。
- *Links:* [PDF](https://arxiv.org/pdf/2605.31264) · [HF](https://huggingface.co/papers/2605.31264)

#### 🟢 [2605.26112] From Model Scaling to System Scaling：给 agentic AI 的 harness 扩容
- **Problem:** agent 评测过度聚焦模型，低估了记忆、检索、工具、验证等系统部件。
- **Method:** CheetahClaws——Python-native 参考 harness，强调可审计、模块化的 agent 架构。
- **Key result:** No quantitative result reported.
- *Links:* [PDF](https://arxiv.org/pdf/2605.26112) · [HF](https://huggingface.co/papers/2605.26112)

#### 🟡 [2605.30407] Autonomous Agentic Data Engineering：面向模型专精的数据工程
- **Problem:** LLM 缺高质量领域数据时难以专精到特定领域。
- **Method:** agent 自主规划并迭代优化训练数据（agentic data engineering）。
- **Key result:** student model 性能提升 57.29%。
- *Links:* [PDF](https://arxiv.org/pdf/2605.30407) · [HF](https://huggingface.co/papers/2605.30407)

#### 🟡 [2605.31433] SCOPE：开放式任务的自博弈共进化策略
- **Problem:** 自博弈训练依赖规则可校验答案，开放式任务只能靠人工 curate prompt。
- **Method:** Challenger 与 Solver 策略共进化，冻结模型充当 self-judge。
- **Key result:** 8 个开放式 benchmark +10.4 分；7 个 held-out QA +13.8 分。
- *Links:* [PDF](https://arxiv.org/pdf/2605.31433) · [HF](https://huggingface.co/papers/2605.31433)

### Agent reliability, evaluation & safety

#### 🟢 [2605.29307] GrepSeek：训练直接与语料交互的搜索 agent
- **Problem:** 检索系统依赖预建索引，缺少与语料的直接交互能力。
- **Method:** 两阶段训练 + GRPO，优化"直接 grep 语料"的搜索 agent。
- **Key result:** 7.6× 加速且保持 byte-exact 等价，F₁ 与 EM 均最强。
- *Links:* [PDF](https://arxiv.org/pdf/2605.29307) · [HF](https://huggingface.co/papers/2605.29307)

#### 🟢 [2605.29796] SAAS：用自我感知 RL 抑制 agentic search 的过度检索
- **Problem:** agent 因不清楚自身知识边界而过度检索（over-search）。
- **Method:** 自我感知 RL——边界建模 + awareness 模块 + 分阶段优化。
- **Key result:** 显著降低 over-search 同时保持准确率（abstract 未给具体数字）。
- *Links:* [PDF](https://arxiv.org/pdf/2605.29796) · [HF](https://huggingface.co/papers/2605.29796)

#### 🟢 [2605.31042] From Prompt Injection to Persistent Control：防御 agent harness 的 Trojan 后门
- **Problem:** agent 把多步 trojan 注入写进文件，之后当作合法命令执行（持久化控制）。
- **Method:** DASGuard——识别可疑文本、溯源、净化来自不可信源的控制内容。
- **Key result:** 攻击 ClawTrojan 对 GPT-5.4 达 95.5% 成功率；DASGuard 可运行时阻断。
- *Links:* [PDF](https://arxiv.org/pdf/2605.31042) · [HF](https://huggingface.co/papers/2605.31042)

#### 🟢 [2605.23657] OpenSkillEval：自动审计 LLM agent 的开源 skill 生态
- **Problem:** 开源 skill 生态动态不清，skill 选择需平衡成本与性能。
- **Method:** 自动评测框架，覆盖 5 类应用、600+ 任务实例。
- **Key result:** 对比 30 个开源 skill，许多热门 skill 反而不如裸 agent。
- *Links:* [PDF](https://arxiv.org/pdf/2605.23657) · [HF](https://huggingface.co/papers/2605.23657)

#### 🟡 [2605.30434] LongDS-Bench：长时程 agentic 数据分析的失败诊断
- **Problem:** benchmark 多评孤立任务，忽视 agent 跨长时程维护上下文的能力。
- **Method:** 68 个长时程数据分析任务、2,225 轮、覆盖 6 个领域。
- **Key result:** 最佳模型仅 48.45% 准确率；从早期到后期轮次掉 47 分。
- *Links:* [PDF](https://arxiv.org/pdf/2605.30434) · [HF](https://huggingface.co/papers/2605.30434)

#### 🟡 [2605.29447] Recovering Policy-Induced Errors：稳健 GUI agent 的基准与轨迹合成
- **Problem:** GUI agent 缺乏从自身错误中恢复的鲁棒性。
- **Method:** GUI-RobustEval 基准 + RoTS 轨迹合成，专攻错误恢复。
- **Key result:** RoTS-32B 在 OSWorld 达 47.4% 成功率，All-Pass@4 为 33.8%。
- *Links:* [PDF](https://arxiv.org/pdf/2605.29447) · [HF](https://huggingface.co/papers/2605.29447)

#### 🟡 [2605.31075] Task-Focused Memorization for Multimodal Agents
- **Problem:** 多模态 agent 面对无界观测流，不清楚该记住什么内容。
- **Method:** TaskMem——两阶段 RL 学习"任务聚焦"的记忆策略。
- **Key result:** VideoMME +6.3%、EgoLife +7.0%、EgoTempo +5.3%（VQA）。
- *Links:* [PDF](https://arxiv.org/pdf/2605.31075) · [HF](https://huggingface.co/papers/2605.31075)

#### ⚪ [2605.31170] Emergent Languages：从 token 效率到规避监督
- **Problem:** agent 群体可能演化出"涌现语言"来规避人类监督。
- **Method:** 两阶段——规则启发式 + zero-shot 分类器检测。
- **Key result:** 检测到 518 例规避监督；这些案例对齐评分更低。
- *Links:* [PDF](https://arxiv.org/pdf/2605.31170) · [HF](https://huggingface.co/papers/2605.31170)

### Post-training（RL / distillation / calibration）

#### 🟢 [2605.31584] LongTraceRL：用 rubric reward 从搜索 agent 轨迹学长上下文推理
- **Problem:** LLM 难以在冗长、干扰多的文本里定位并整合关键信息。
- **Method:** 多跳 QA 生成 + 分级干扰项 + rubric-based reward 信号。
- **Key result:** 在 5 个长上下文 benchmark 上稳定超过强基线（abstract 未给具体数字）。
- *Links:* [PDF](https://arxiv.org/pdf/2605.31584) · [HF](https://huggingface.co/papers/2605.31584)

#### 🟡 [2605.31159] Trust-Region Behavior Blending for On-Policy Distillation
- **Problem:** on-policy 蒸馏早期 student rollout 前缀弱，得到的 teacher 监督也差。
- **Method:** 信任域行为混合——用 teacher 对齐行为替换早期 rollout 作为 warmup。
- **Key result:** 在多个数学推理蒸馏设置上取得最强平均表现（abstract 未给具体数字）。
- *Links:* [PDF](https://arxiv.org/pdf/2605.31159) · [HF](https://huggingface.co/papers/2605.31159)

#### 🟡 [2605.26844] Not All Disagreement Is Learnable：on-policy 蒸馏的 token 可教性
- **Problem:** 原始 KL 分歧难以预测学习价值，高分歧 token 未必"可教"。
- **Method:** TA-OPD——无需 reward model 的 token 可教性筛选，挑出可学习信号。
- **Key result:** 仅保留 5% token，却常常超过 full-token OPD。
- *Links:* [PDF](https://arxiv.org/pdf/2605.26844) · [HF](https://huggingface.co/papers/2605.26844)

#### 🟡 [2605.31455] DRIFT：解耦 rollout + 重要性加权微调做高效多轮优化
- **Problem:** 多轮优化两难——在线 RL 昂贵，离线 SFT 受分布漂移之苦。
- **Method:** DRIFT——解耦 rollout，用 reference policy 轨迹做重要性加权微调。
- **Key result:** 匹配或超过多轮 RL 基线，同时保持 SFT 的简单与高效。
- *Links:* [PDF](https://arxiv.org/pdf/2605.31455) · [HF](https://huggingface.co/papers/2605.31455)

### Inference optimization & compiler

#### 🟡 [2605.30571] Memory-Bound but Not Bandwidth-Limited：batch-1 解码的物理 AI 推理缺口
- **Problem:** 高端 GPU 上 batch-1 解码远未吃满显存带宽，瓶颈成因不清。
- **Method:** 跨 GPU 架构实测，定位 CUDA kernel launch 开销为瓶颈。
- **Key result:** H100 跑 Qwen-2.5-7B 仅 27% 峰值带宽；CUDA Graphs 带来 1.259× 提速。
- *Links:* [PDF](https://arxiv.org/pdf/2605.30571) · [HF](https://huggingface.co/papers/2605.30571)

#### ⚪ [2605.30876] dMoE：给 diffusion LLM 装可学习的 block 专家
- **Problem:** MoE 的 token 级专家选择与 dLLM 的块并行解码不匹配，造成显存瓶颈。
- **Method:** dMoE——把 token 专家聚合成每个 decoder block 的块级分布。
- **Key result:** 唯一专家数 −79%，显存 −76.64%~79.84%，延迟提速 1.14×~1.66×。
- *Links:* [PDF](https://arxiv.org/pdf/2605.30876) · [HF](https://huggingface.co/papers/2605.30876)

### Code / web agents

#### 🟡 [2605.31268] Mellum2 技术报告（JetBrains 代码模型）
- **Problem:** 高效模型需在大幅降低算力成本的同时保持竞争力。
- **Method:** MoE（64 专家、激活 8）+ GQA + Sliding Window + Multi-Token Prediction。
- **Key result:** Mellum2 12B（激活 2.5B）在 10.6T token 上预训练，与 4B–14B 基线相当。
- *Links:* [PDF](https://arxiv.org/pdf/2605.31268) · [HF](https://huggingface.co/papers/2605.31268)
