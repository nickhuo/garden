## Part 2 — Research Radar（HuggingFace Papers，2026-06-12）

### TL;DR — 本日 research 风向
两条主线压倒性主导：**agent 的"演化/自修复"**（记忆演化、推理时工作流进化、演化式基准）与 **agent 评估的"防作弊"**（抗捷径搜索、混合界面 computer-use、抗污染基准）。底层则是一波扎实的 **RL / 推理优化** 工程（稀疏注意力、分层投机解码、邻域混合 GRPO）。整体信号：业界已默认 agent 能跑，焦点全面转向**让它在变化的环境里跑得稳、且别在评测里作弊**。

### Agent frameworks & self-evolution

### 🟢 [2606.13681] EvoArena — agent 记忆演化
- **Problem:** agent 多在静态环境评测，真实部署里界面/规则/代码状态/偏好持续变化。
- **Method:** EvoMem，把记忆记成结构化「更新历史」补丁，让 agent 通过记忆变化推断环境演化。
- **Key result:** EvoArena 上 +1.5%（base 39.6%），GAIA +6.1%、LoCoMo +4.8%。
- *Links:* [PDF](https://arxiv.org/pdf/2606.13681) · [HF](https://huggingface.co/papers/2606.13681)

### 🟢 [2606.12882] HarnessBridge — 可学习 agent harness
- **Problem:** agent 长任务高度依赖 harness，但 harness 全靠手工工程，难随复杂度扩展。
- **Method:** 轻量可学习控制器，双向投影：observation 投影压缩轨迹为决策态，action 投影把动作译成可执行转移或拒绝；统一指令微调训练。
- **Key result:** abstract 称在 Terminal-Bench 2.0 / SWE-bench Verified 上「匹配或超越专用 harness、且大幅降 token 与轨迹长度」，未给具体数字（No quantitative result reported）。
- *Links:* [PDF](https://arxiv.org/pdf/2606.12882) · [HF](https://huggingface.co/papers/2606.12882)

### 🟡 [2606.12674] Evoflux — 推理时进化的工具工作流
- **Problem:** 小模型在 live 工具发现 / schema 校验 / 依赖追踪上吃力，微调难学到 plan 修复行为。
- **Method:** 推理时演化搜索，通过结构化编辑 + 执行反馈 + 多样性剪枝演化「带类型的工作流图」，不更新权重。
- **Key result:** MCP-Bench（250 工具）执行可行性从 ~3% 升到 17–24%；同数据的 SFT/SFT+DPO 反而塌到 zero-shot 之下。
- *Links:* [PDF](https://arxiv.org/pdf/2606.12674) · [HF](https://huggingface.co/papers/2606.12674)

### Agent reliability, evaluation & safety

### 🟢 [2606.09426] WeaveBench — 混合界面 computer-use 基准
- **Problem:** 现有 CUA 基准只测 GUI 或 CLI 单一界面，生产工作流要求跨模态协调。
- **Method:** 114 任务跨 8 个真实域，每个任务强制 GUI 观察 + CLI/代码修改在同一轨迹内；用 trajectory-aware agentic judge 审多轮证据。
- **Key result:** 最佳 Claude Opus 4.7 仅 41.2%（Claude Code runtime）；单通道塌到 ≤3.5%；失败主因 reward hacking 35.2% / long-horizon 崩坏 30.4%。
- *Links:* [PDF](https://arxiv.org/pdf/2606.09426) · [HF](https://huggingface.co/papers/2606.09426)

### 🟡 [2606.13120] EvoBrowseComp — 抗污染的搜索 agent 基准
- **Problem:** BrowseComp 等静态基准易被训练语料污染，模型靠记忆而非真检索答题。
- **Method:** 三 agent 协作从 live web 合成 800 题（中英各 400），用「训练截止后的新知识」防记忆，并以推理图消冗余/捷径。
- **Key result:** 无工具时 Claude-Opus-4.6 仅 6.0–10.3%，带工具 44.8%（最佳）；87% QA 通过人工验证，90% 题需跨 ≥3 源。
- *Links:* [PDF](https://arxiv.org/pdf/2606.13120) · [HF](https://huggingface.co/papers/2606.13120)

### 🟡 [2606.12087] FORT-Searcher — 抗捷径的深度搜索训练
- **Problem:** 现有深搜数据「结构复杂」但 agent 可走捷径（一条线索定位答案、单源凑齐多事实）绕过真检索。
- **Method:** FORT 四阶段控捷径：长尾实体 + 环状结构初始化、异源衍生事实、隐藏中间实体名/模糊数值、对抗精修。
- **Key result:** BrowseComp 72.2%（vs MiroThinker-1.7-mini 67.9%）；prior-shortcut 率降到 11.0%（开源数据 27.0%）；仅 ~3B 活跃参数 + SFT。
- *Links:* [PDF](https://arxiv.org/pdf/2606.12087) · [HF](https://huggingface.co/papers/2606.12087)

### 🟡 [2606.12451] ToolSense — 审计 LLM 的参数化工具知识
- **Problem:** 参数化工具检索在标准基准上 ~95%，但可能只是「模式匹配 token id」，并不真懂工具。
- **Method:** 从工具目录自动生成 RRB（真实意图短查询）+ MCQ/QA 探针 + Internalization Score（对比自由 vs 约束解码）。
- **Key result:** RRB 比同分布基准暴跌 50–64 个百分点；最佳参数模型 44.4% recall 反低于 embedding 基线 55.6%；事实探针近随机（MCQ 31.4%）。
- *Links:* [PDF](https://arxiv.org/pdf/2606.12451) · [HF](https://huggingface.co/papers/2606.12451)

### Post-training (RL, distillation, calibration)

### 🟡 [2606.13473] MaxProof — 生成-验证 RL + 群体级测试时扩展
- **Problem:** 竞赛级数学证明无可执行 ground truth，生成式验证器带噪声、易被 reward gaming。
- **Method:** 训练「生成/验证/修复」三能力并合并为单模型，推理时在证明群体上锦标赛搜索；四层防御验证器 + CISPO RL。
- **Key result:** IMO 2025 35/42（one-shot 27/42，+8）；USAMO 2026 36/42（+10）；IMOProofBench 67.40。
- *Links:* [PDF](https://arxiv.org/pdf/2606.13473) · [HF](https://huggingface.co/papers/2606.13473)

### 🟡 [2606.13679] InterleaveThinker — 强化 agentic 交错生成
- **Problem:** 图像生成器受架构限制无法产出图文交错序列；统一多模态模型有视觉过度依赖 + 步间误差累积。
- **Method:** Planner/Generator/Critic 三 agent 框架，先一次性规划 N 步指令，双奖励（accuracy + step-wise）经 GRPO 单步强化。
- **Key result:** WISE 从 0.47 → 0.73（4 步 FLUX.2-klein）；RISE 13.3 → 28.9；UEval 67.2（Qwen-Image-Edit）。
- *Links:* [PDF](https://arxiv.org/pdf/2606.13679) · [HF](https://huggingface.co/papers/2606.13679)

### 🟡 [2606.10768] N-GRPO — 嵌入级邻域混合的策略优化
- **Problem:** token 级采样产冗余轨迹，嵌入级加噪又破坏语义一致性。
- **Method:** rollout 阶段做 Semantic Neighbor Mixing：取 anchor token 的 k 近邻嵌入加权混合 + 随机门控，扰动限制在语义流形内。
- **Key result:** DeepSeek-R1-Distill-Qwen 7B Pass@32 82.53 → 84.20；1.5B 在 AIME25 +2.97。
- *Links:* [PDF](https://arxiv.org/pdf/2606.10768) · [HF](https://huggingface.co/papers/2606.10768)

### Inference optimization & compiler

### 🟢 [2606.13392] MiniMax Sparse Attention — 长上下文稀疏注意力
- **Problem:** softmax 注意力的二次成本让百万级上下文在部署规模上不可行。
- **Method:** MSA，基于 GQA 的分块稀疏：轻量 Index Branch 选 top-k KV 块，Main Branch 仅对选中块做精确注意力。
- **Key result:** 1M 上下文 per-token 注意力计算降 **28.4×**；H800 上 prefill 14.2×、decode 7.6× 加速，109B MoE 上与 full GQA 持平。
- *Links:* [PDF](https://arxiv.org/pdf/2606.13392) · [HF](https://huggingface.co/papers/2606.13392)

### 🟡 [2606.12243] VIA-SD — 模型内路由的投机解码
- **Problem:** 投机解码是二元「接受/全量重算」，但很多被拒 token 用轻量子模型即可验证。
- **Method:** 多层分级：高置信直通、中置信走模型内 slim-verifier 路由、不确定才全量验证；无需改训练。
- **Key result:** 拒绝率降 0.10–0.22；较 SD 基线提速 10–20%；相对无 draft 解码加速 2.5–3×。
- *Links:* [PDF](https://arxiv.org/pdf/2606.12243) · [HF](https://huggingface.co/papers/2606.12243)
